# 术语库与冲突处理

术语库是这套工具保证「同一本书里同一个词始终译成同一个说法」的机制。
它分三层，优先级从高到低，**下层不能覆盖上层**：

| 层 | 文件 | 作用范围 | 谁能写 |
| --- | --- | --- | --- |
| 全局 | `config/glossary.json` | 所有作品 | 侧栏「全局术语库」页（或「指定术语 → 全局术语库」），也可直接编辑该文件；自动流程**永不覆盖** |
| 作品 | `<作品>/glossary.json` | 整本书 | 面板「指定术语 → 整本书」 |
| 作品累计 | `<作品>/global_glossary_tracker.json` | 整本书 | 翻译时自动重建（只读视图，不建议手改） |
| 章节 | `<作品>/glossary_<章号>.json` | 该章 | 翻译时写入；面板「指定术语 → 仅本章」 |

解析顺序：**作品术语库 ＞ 全局 `config/glossary.json` ＞ 章节术语库**。

## 先到先得

默认规则是**严格先到先得**：某个中文词第一次被定下某个译法后，后续章节再出现
就该沿用这个译法。如果模型给出不同的写法，**不会静默改掉**，而是：

1. 拦截本次改动；
2. 把这条冲突追加到 `<作品>/glossary_conflicts.jsonl`；
3. 在面板「术语库 → 冲突」页列出来，供你判断。

确认确实要改时，用 `--allow-term-changes`（命令行）或面板里带「强制覆盖」的操作。
**全局 `config/glossary.json` 永远不可被自动覆盖**——要改就手工编辑那个文件。

冲突记录逐行一个 JSON，包含词条、旧译法、新译法、来源章节等；直接读这个文件也能审计。

## 查看与维护

- 面板**每部作品**的「术语库」页有三个标签：**术语总表**（按首次出现章节，只列这部作品的
  词条）、**按章**（一章一张卡片，卡内三列）、**冲突**（`glossary_conflicts.jsonl` 流水）。
  页面底部会提示"另有 N 条全局术语库的词条对所有作品生效"，并可一键跳到全局术语库。
- 侧栏的**「全局术语库」**是独立入口（不属于任何作品），按四类分类列出、可搜索、
  可新增/修改，带实时查重。

### 术语分四类

| 类别 | 值的形态 | 说明 |
| --- | --- | --- |
| 固定术语 | 纯英文译名 | 全篇统一，不接受语境说明 |
| 语境术语 | 语境 → 不同译法 | 必须填语境说明，同一个词可按语境给不同译法 |
| 美学表达 | 说明文字（可含中文） | 修辞、句子处理的约定 |
| 文化虚指 | 说明文字（可含中文） | 数字、称谓等文化含义的说明 |

前两类的**词条必须是中文原词、译法必须是纯英文**；后两类是给人看的说明，不受此限。
固定术语填了语境会被明确拒绝（而不是悄悄丢掉），要按语境区分译法请改选「语境术语」。
- 「＋ 指定术语」可以手工登记词条，输入时会实时查重，并告诉你是哪个层已经定过它；
  已存在的词条会**回写到最早确立它的那一章**，而不是随手写在当前章。
- 命令行查看累计冲突：

  ```bash
  python scripts/translate.py --dir my-novel --show-conflicts
  ```

## 语料重建与 RAG

- **重建本章术语**：默认写术语库是**合并**语义——同名键更新、本次没提到的保留。
  这样你手工预登记到未来章节的词条不会被翻译抹掉。需要"丢弃旧词条、按本次译文
  整体重建"时，用 `--rebuild-glossary`（面板「本章操作」里也有勾选项，勾上会提示
  将丢弃多少条）。
- **RAG 检索**：`--rag` 会让模型在定译法前先看这个词在全书其它地方是怎么用的
  （默认只看后文，可用 `--rag-scope` 改）。它只影响提示词，不改术语库；
  检索范围与预算由 `--rag-terms` / `--rag-snippets` / `--rag-window` / `--rag-budget` 控制。

## 精修时的术语注入

**精修（refine）不注入本章自己确立的术语。**

原因：`glossary_<章号>.json` 里的词条多数是自动产出的（翻译或上一轮精修时模型自己定的
译法）。精修是"就地改写"，用户的要求往往正是"这个词该换个译法"；如果把本章词条也当成
"既定译法"注入，模型会以"术语库既定"为由不敢改。

- **仍然注入**：全局 `config/glossary.json` 与作品级 `<作品>/glossary.json`（人工确立的基准），
  以及**更早章节**确立的译法；
- **不注入**：正在精修这一章的 `glossary_<章号>.json`；
- 整章翻译与局部重译**不受影响**：翻译第 N 章时本来就只注入第 0..N-1 章（不含本章），
  局部重译则保留"既定译法不可借重译之名替换"的行为。

## 常见情况

**模型把专有名词译错了，怎么锁定正确译法？**
在面板「术语库 → ＋ 指定术语」里登记，作用范围按需要选「仅本章」或「整本书」，
带上语境说明。登记完重译相关段落即可。

**同一本书里人名前后不一致。**
多半是某个译法先在某章定下、后续章节没沿用。先看「冲突」页有没有记录；
没有记录说明是不同写法各自被接受过，用「指定术语 → 整本书」把它统一，
再对不一致的章节做局部重译。

**想给所有作品统一一套译法（比如功法等级、货币单位）。**
在「指定术语」里把**作用范围**选成「**全局术语库（所有作品共用）**」——它会写进 `config/` 下的
`glossary.json`，对所有作品生效，且自动流程永远不会覆盖它。也可以直接编辑那个文件。
术语总表里这类条目会标成「全局」。

**全局术语怎么改？**
它是最高基准：从章节层改不动它（会提示改作用范围）。把作用范围选成「全局术语库」、
勾上「强制覆盖」再保存即可。
